# TRUECSS Continuity Backfill Audit — 2026-09-18

Status: CANONICAL PROCESS AUDIT

## Question

Did the same continuity failure later identified in MSF also occur during CSS/trueCSS development — namely, did a local correction or optimization sometimes replace unrelated settled architecture instead of integrating into it?

Answer: yes. The historical record shows multiple architecture substitutions mixed into what was being treated as one continuing line. It also shows some good surgical iterations that should be preserved as the model for future work.

## Original trueCSS subject — v1.0

The v1.0 protocol is unusually clear about the subject under test.

Frozen architecture:
- exactly 1,000,000 reusable physical representational nodes;
- one active chronological page condition q;
- no stored page bank;
- no page-specific copy of theta;
- no growing relation-node store;
- no per-position selectors;
- no residual/correction stream;
- fixed node count, node width, precision, topology/generic law and representation format before source teaching;
- page turns must change only the effective relational formation of the same substrate;
- when a candidate law fails, reject the law and retry while keeping the trueCSS invariants unchanged.

This is the correct continuity rule in substance: improve the settling/binding law, not the subject being tested.

## Historical pre-v1.0 drift already recognized

Section 19 of v1.0 explicitly records earlier experiments that had drifted away from the intended subject:
- explicit stack/reference replay;
- fixed-disk q signaling;
- theta-plus-q reflexes;
- relation-attention;
- context-state graphs;
- page-folded graphs;
- append-only relational book graphs.

The protocol correctly classifies these as useful evidence but not trueCSS when they use explicit per-position storage, growing append-only relation nodes, page roots/banks, or q merely relocating stored cells.

This shows the replacement problem was already visible before v1.0 and v1.0 was an attempt to stop it.

## v1.0 -> v1.1 Section 26 — architecture change, not a local correction

v1.1 adds an explicitly authoritative section titled:

“v1.1 ARCHITECTURAL CORRECTION — BIT SUBSTRATE / CONDITIONAL TERMINAL ROUTING”

It states that where Sections 2–25 imply one independently serialized value per logical node, Section 26 supersedes that interpretation.

The physical subject changes from:
- exactly 1,000,000 reusable physical nodes with fixed per-node width

to:
- an arbitrary fixed binary substrate S with a working <=50,000,000-byte budget;
- logical nodes, terminal channels, recursive states, page formations and relations may be generated in numbers far exceeding the stored bits;
- the one-million-node language becomes largely logical rather than the literal physical substrate constraint.

Several important invariants survive:
- fixed retained source-dependent capacity;
- one active chronological condition;
- no page bank;
- no residual/correction stream;
- cold replay;
- full byte accounting.

But the physical representational claim itself changes substantially.

Under the new continuity discipline, this should have been forked as a new architecture family — for example TRUECSS-BIT-SUBSTRATE — rather than appended as a correction that superseded the original physical-node interpretation while retaining the same canonical identity.

Classification: ARCHITECTURE REVISION, not surgical optimization.

## ACT206 V1 — valid candidate under the v1.1 bit-substrate family

ACT206 V1 freezes:
- 50,000,000-byte total ceiling;
- 512 bytes reserved;
- no page-bank bytes;
- no residual bytes;
- no correction bytes;
- one chronological target exposed at a time;
- 206 output terminal states.

It tests three source-independent relational routing laws and records where each first becomes contradictory.

Measured best V1 law:
- CONTEXT_RECURSIVE;
- 24,744,565 exact sequential imprints before first contradiction;
- no freeze/cold-replay promotion.

This is a good falsification experiment because the architecture remains fixed during comparison and only the relational routing law changes.

Classification: VALID CONTROLLED EXPERIMENT within the v1.1 family.

## ACT206 V1 -> V2 — good surgical iteration

V2 keeps:
- the same 50 MB budget;
- same 512-byte reserve;
- same 1,000,000-byte page chronology;
- same 206 terminals;
- same one-target-at-a-time parser;
- same no-page-bank/no-correction intent.

The primary change is the relation law: V1 pair relations are generalized into a more expressive affine relation form so the same retained carrier can participate in more conditionally distinguishable constraints.

That is exactly the kind of iteration we want:
- failed component identified;
- improvement target = relational expressivity;
- surrounding architecture retained.

Classification: VALID SURGICAL OPTIMIZATION.

## RiddlerV1 / APC — major architecture drift

Section 28 later introduces “RiddlerV1 / Adaptive Puzzle Compression.”

It permits:
- each conceptual page to choose a different generic puzzle family;
- page-specific source-derived clues;
- page-specific family identifiers, counts, ranks, dictionaries, seeds, parameters or references;
- total representation measured as the sum of those page-specific clue payloads.

This preserves honest accounting and exact-replay requirements, but it changes the core trueCSS representational mechanism.

Original trueCSS:
same fixed source-dependent substrate
+ q
-> regenerated page formation

APC:
generic solver library
+ independently retained page-specific puzzle/clue descriptions
-> page reconstruction

The latter is a legitimate lossless-compression research architecture, but it is no longer the fixed-substrate/page-conditioned-overlap hypothesis. Source-dependent retained state is explicitly accumulated as page clues.

Under the new continuity rule, APC should have been a separate compressor family/branch rather than an authoritative continuation inside the trueCSS protocol.

Classification: ARCHITECTURE REPLACEMENT accidentally folded into trueCSS.

## Hutter fixed-state bot — separate research line, not trueCSS

The later fixed-state predictor/arithmetic-code work uses:
fixed generic adaptive model
+ bounded runtime state regenerated during decode
+ compressed residual bitstream
-> exact source.

That is a valid conventional/model-based compression architecture and has its own accounting discipline.

It is not trueCSS because the original trueCSS protocol explicitly forbids residual/correction streams as the mechanism that rescues exactness.

The Hutter target document mostly treats it correctly as a separate Track B. It should remain separate.

Classification: SEPARATE COMPRESSION ARCHITECTURE.

## EIS / trueCSS equivalence period — another replacement risk

The later TRUE EIS corrected handoff states that EIS is:
source
-> synchronized tonal controls
-> composite signal
-> listener
-> optional HMC/CSS/Domino assembly
-> exact source.

It explicitly says CSS/Domino may be an additional organization layer and is secondary to the EIS representation.

Therefore EIS is not an implementation of the original trueCSS fixed relational substrate. Treating EIS as equivalent to trueCSS, or allowing EIS to supersede trueCSS mechanics, would again replace the subject rather than improve one CSS component.

Classification: DISTINCT ARCHITECTURE / POSSIBLE INTEGRATION LAYER, not trueCSS continuation.

## Reconstructed trueCSS lineage

The clean lineage should be separated into families.

### TRUECSS-ORIGINAL
Core subject:
exactly 1,000,000 physical reusable nodes
+ one active q
+ changing relational formation
+ no retained per-page payload
+ no capacity/precision growth.

Permitted iteration:
change settling/binding/routing law only, with minimum integration changes.

### TRUECSS-BIT-SUBSTRATE
Core subject:
fixed <=50 MB binary source-dependent substrate S
+ chronology/context-conditioned generated logical carriers
+ no page bank/residual/correction
+ exact cold replay.

ACT206 V1 and V2 belong here.

This family is related to original trueCSS but is not identical to it.

### APC / RIDDLER
Core subject:
adaptive page-local puzzle selection
+ counted page-specific clues
+ generic solver
+ exact reconstruction.

Separate compressor family.

### FIXED-STATE BOT
Core subject:
bounded adaptive predictor
+ arithmetic-coded residual stream.

Separate model-based compressor.

### EIS/MSF
Core subject:
simultaneous signal representation
+ mixed retained track/field
+ audience/listener separation.

Separate signal-compression family that CSS techniques may optionally organize, but does not replace CSS.

## Main finding

The user's suspected failure mode is strongly supported by the record.

The most important instance is not a small implementation bug. The canonical trueCSS document itself first says failed laws must be retried “while keeping the trueCSS invariants unchanged,” then later:
1. supersedes the physical-node interpretation with a different bit-substrate architecture; and
2. adds APC, which changes fixed-substrate overlap into accumulated page-specific puzzle clues.

Those are useful ideas, but they should have been forks/layers, not silent replacements of the same subject.

That explains why parts of the CSS lineage can feel as if a correction solved one issue while something previously important disappeared: the implementation process sometimes optimized by redefining the substrate rather than preserving it.

## Continuity rule to apply retroactively

For every future CSS-family experiment:

1. Name the architecture family first.
2. Freeze its invariants before coding.
3. Name one optimization target.
4. Permit only minimum integration changes.
5. Diff the resulting architecture against the frozen version.
6. If any unrelated invariant changes, fork a new architecture family.
7. Never let a successful new family erase the earlier one.
8. Compare families only after each has its own exact cold-replay evidence.

## Immediate consequence

Original trueCSS should be preserved as an unresolved fixed-one-million-node hypothesis rather than considered superseded by bit-substrate, APC, EIS or MSF work.

ACT206 V1/V2 should be preserved as evidence for the distinct fixed-bit-substrate family.

APC should be preserved as its own adaptive-puzzle compressor.

EIS/MSF should remain its own signal architecture, with CSS techniques integrated only when explicitly declared as an added layer.

This backfill restores the missing lineage instead of choosing one historical reinterpretation as though it had always been the design.

# TruCompute Continuous Three-State Architecture v10

**Date:** 2026-09-18  
**Status:** CANONICAL SEMANTIC CORRECTION

## Core correction

TruCompute has no OFF/NEITHER lifecycle inside the computational field.

The native domain is uninterrupted:

\`\`\`
NEG / BOTH / POS
\`\`\`

BOTH is not conventional numeric zero and is not an OFF state.

It is the continuously present unresolved substrate condition of every data node.

## Continuous selector transitions

A page-letter probe resolves a node:

\`\`\`
BOTH substrate + (P_q, C_c) -> POS or NEG
\`\`\`

Changing the selector is a direct change of applied condition:

\`\`\`
(P_q,C_a) -> (P_q,C_b) -> (P_r,C_b) -> ...
\`\`\`

There is no intermediate:

\`\`\`
OFF
NEITHER
reset
clear-to-zero
recompute-from-zero
\`\`\`

The field remains present throughout.

## Data-node law

Every data node exists continuously and every valid page-letter probe resolves it:

\`\`\`
N_i(P_q,C_c) =
    POS  if character c is true at position i on page q
    NEG  otherwise
\`\`\`

No data node opts out of an active probe.

## Activators

All page and character activators physically/logically belong to the generic machine.

Selection changes which page-letter condition is applied.

An unselected activator is simply not the selected condition; this does not create a NEITHER state in the data field.

## Architectural consequence

Future TruCompute node implementations, including native resistor/transfer nodes, must preserve:

- uninterrupted three-condition substrate;
- no OFF/NEITHER computational state;
- no reset between selector changes;
- direct selector-to-selector response;
- BOTH as native unresolved coexistence;
- POS/NEG as condition-resolved observation;
- observation must not destroy or rewrite the underlying imprint.

# trueCSS 3bit — Public Replication Protocol v0.1

**Date:** 2026-09-18  
**Project:** Epsilonic / trueCSS  
**Status:** Experimental public replication specification. No compression result is claimed until the complete source-isolated replay gate passes.

## 1. Purpose

This document defines a public, reproducible test of a fixed-capacity relational substrate.

The experiment asks whether a fixed graph of reusable physical nodes can absorb a much longer exact chronology by storing information in balanced signed relationships rather than by allocating a new storage cell for every source position.

The subject under test is intentionally narrow. Later or adjacent Epsilonic architectures are not substituted into this experiment.

## 2. Canonical test source

Primary public test corpus:

- canonical enwik9
- source size: 1,000,000,000 bytes
- SHA-256: `159b85351e5f76e60cbe32e04c677847a9ecba3adc79addab6f4c6c7aa3744bc`
- MD5: `e206c3450ac99950df65bf70ef61a12d`
- observed terminal alphabet: 206 byte values

First applicability gate:

- first 100,000,000 bytes of canonical enwik9
- previously verified prefix SHA-256: `2b49720ec4d78c3c9fabaee6e4179a5e997302b3a70029f30f2d582218c024a8`

A full trueCSS claim requires the complete canonical 1 GB replay gate. The 100 MB test is an engineering applicability stage only.

## 3. Frozen architecture

The following are fixed for this experiment:

- exactly 1,000,000 reusable physical nodes;
- one active chronological page condition at a time;
- conceptual page length of 1,000,000 source positions;
- one source target exposed to the learning law at a time;
- no stored page bank;
- no page-specific snapshot payload;
- no residual stream;
- no correction stream;
- no source-sized position selector;
- no chronology-dependent node-count growth;
- no chronology-dependent node-width growth;
- no source-specific hidden decoder constants;
- exact source-isolated cold replay is mandatory.

A failed relation law is replaced or refined without changing these frozen conditions.

## 4. Fixed graph substrate

Each physical node owns four fixed relation slots.

Each slot has a signed relational weight in:

```
-1, 0, +1
```

The destination of every slot is regenerated by a source-independent topology function. Topology therefore does not consume source-dependent storage.

For the reference implementation, four relation weights are packed into one byte:

```
4 relation slots × 2 serialized bits = 8 bits per physical node
```

Therefore the source-dependent graph-weight substrate is fixed at:

```
1,000,000 nodes × 1 byte = 1,000,000 bytes
```

This byte count does not grow as chronology advances.

## 5. Inactive zero and active zero

The experiment distinguishes two states with the same scalar total.

Inactive zero:

```
(0, 0)
net = 0
activity = 0
```

No relation is participating.

Active zero:

```
(+1, -1)
or
(-1, +1)

net = 0
activity = 2
```

Two opposing relations are present and balanced.

Therefore the resolver must not treat scalar sum alone as the represented state.

The observable relation includes:

```
net field
+ activity
+ relational orientation
```

The distinction between inactive and active zero is part of the architecture.

## 6. Relational orientation

A balanced pair has global sign symmetry. If every sign in one connected component is inverted, the underlying relation should retain the same meaning.

For this reason, logical orientation is measured relative to another active relation selected by the same source-independent routing law.

For a routed triple of graph relations `a`, `b`, and `reference`:

```
live-zero condition:
sign(a) != sign(b)

orientation decision:
sign(a) relative to sign(reference)
```

No physical node or graph edge has a universal absolute positive or negative semantic meaning.

The information exists in the relation among active weights.

## 7. Terminal representation

Canonical enwik9 uses 206 observed terminal byte identities.

The reference resolver uses eight balanced relational decisions per terminal, providing:

```
2^8 = 256
```

possible terminal identities.

The source-specific mapping between observed bytes and terminal codes is retained in the frozen artifact and counted as metadata.

This mapping does not alter graph capacity as chronology advances.

## 8. Chronological conditioning

For source position `t`:

```
q = floor(t / 1,000,000)
k = t mod 1,000,000
```

The routing law deterministically combines:

- chronological page condition `q`;
- local page position `k`;
- recursively regenerated prior-output context;
- terminal-decision index.

Those values select the graph relations participating in the current decision.

The page condition does not select a stored page.

Instead:

```
same fixed graph
+ different q/context
-> different effective relational formation
```

This is the core trueCSS hypothesis under test.

## 9. Teaching procedure

For every source byte, in chronological order:

1. compute `q`, `k`, and the current deterministic context;
2. expose only the current source terminal to the teaching rule;
3. map the terminal to its fixed decision pattern;
4. for each decision, generate the participating graph relations;
5. require the selected pair to be active and opposing;
6. require its orientation relative to the generated reference relation to match the target after the generic modifier;
7. retain all previously imposed relational constraints;
8. advance only if the new target is compatible with the same fixed graph.

The teaching process may use working memory that is discarded before replay.

Training memory is not itself the compressed artifact.

## 10. Contradiction rule

If a new target requires a relation incompatible with previously retained constraints, the candidate relation law has failed.

The run must report:

- exact byte count absorbed before contradiction;
- page number;
- local page position;
- terminal-decision slot;
- observed terminal count;
- physical node count;
- fixed node width.

A contradiction falsifies the tested routing/settling law.

It does not justify adding page storage, residual corrections, hidden capacity, or larger nodes.

## 11. Freeze procedure

If the requested source span is absorbed without contradiction:

1. collapse the training-only relation solver into the fixed graph-weight substrate;
2. leave unused relation slots at zero;
3. settle participating relations to signed active states;
4. serialize exactly one byte per physical node;
5. append only explicitly counted metadata;
6. hash the complete frozen artifact;
7. verify generic replay while the source still exists;
8. remove the source and all training-only artifacts.

Only the frozen graph and the generic reader may remain for the cold-replay test.

## 12. Cold replay

The reader must reconstruct the chronology using only:

- the frozen graph weights;
- counted terminal-map metadata;
- generic topology law;
- generic chronological routing law;
- generic relational resolver.

For every chronological position, the reader:

1. regenerates the same relation triple;
2. checks that the routed pair is active;
3. verifies that its signed weights cancel to active zero;
4. measures orientation relative to the generated reference relation;
5. removes the generic modifier;
6. reconstructs the terminal code;
7. maps the terminal code back to its exact source byte;
8. updates the deterministic context;
9. advances to the next source position.

No semantic repair, source dictionary lookup, network access, or hidden page information is permitted.

## 13. Exactness gate

A run passes only when all of the following hold:

- requested byte count is fully reconstructed;
- every reconstructed byte equals the source byte;
- reconstructed SHA-256 equals the source SHA-256;
- no source-derived file outside the measured frozen artifact is used;
- physical node count remains exactly 1,000,000;
- node width remains exactly one byte;
- no retained page bank, residual, or correction stream exists.

One incorrect byte is failure.

## 14. Size accounting

The complete frozen representation must count:

- 1,000,000-byte graph-weight substrate;
- format header;
- observed-byte/terminal mapping;
- any source-dependent metadata required for exact replay.

Do not count:

- temporary training structures discarded before freeze;
- generic source-independent decoder code when reporting carrier-only size.

For broader compression competitions or packaged scores, decoder/package bytes must be reported according to the rules of that benchmark.

## 15. Evidence terminology

**CANONICAL**  
Frozen architecture or protocol currently defining the experiment.

**MEASURED**  
Directly executed result with recorded source identity, artifact accounting, and replay outcome.

**EXPERIMENTAL**  
Implemented mechanism that has not passed the complete canonical gate.

**PROJECTED**  
Derived or extrapolated value not directly measured at the stated corpus size.

**FAILED**  
The tested relation law or replay did not satisfy a required gate.

**trueCSS PASS**  
Reserved for a specification-conformant implementation that completes the full canonical freeze, source-removal, cold-replay, byte-equality, and SHA-256 gates.

## 16. Continuity discipline

Every revision must declare before implementation:

- frozen invariants;
- one optimization target;
- minimum required integration changes;
- measurable acceptance criterion.

A local improvement must not silently alter unrelated architecture.

If a proposed improvement changes another frozen invariant, it must become a separate architecture branch instead of replacing this one.

## 18. Public replication commands

Clone the repository:

```bash
git clone https://github.com/MungSauce/Dynamic-Field-Theory.git
cd Dynamic-Field-Theory
git checkout truecss-3bit-20260918
```

Fetch canonical enwik9:

```bash
curl -L --fail --retry 4 --retry-delay 5 \
  -o enwik9.zip https://mattmahoney.net/dc/enwik9.zip
```

Extract the first 100 MB:

```bash
python3 - <<'PY'
import hashlib
import zipfile

with zipfile.ZipFile("enwik9.zip") as z, \
     z.open("enwik9") as src, \
     open("enwik100m", "wb") as out:
    left = 100_000_000
    h = hashlib.sha256()
    while left:
        chunk = src.read(min(8 << 20, left))
        if not chunk:
            raise SystemExit("unexpected EOF")
        out.write(chunk)
        h.update(chunk)
        left -= len(chunk)

print(h.hexdigest())
PY
```

Expected SHA-256:

```
2b49720ec4d78c3c9fabaee6e4179a5e997302b3a70029f30f2d582218c024a8
```

Build:

```bash
g++ -O3 -std=c++17 \
  experiments/truecss_3bit_graph_v3.cpp \
  -o truecss_graph
```

Teach the fixed graph:

```bash
./truecss_graph train \
  enwik100m \
  truecss_graph.state \
  100000000
```

If teaching reaches `status=FROZEN`, remove the source before replay:

```bash
rm enwik100m
```

Cold replay:

```bash
./truecss_graph replay \
  truecss_graph.state \
  recovered.bin
```

A successful run must report:

```
status=REPLAY_PASS
recovered_bytes=100000000
```

The recovered output must independently hash to the canonical 100 MB prefix value.

## 20. Defining principle

trueCSS tests whether a fixed relational graph can express a chronology much larger than itself because the same physical substrate can participate in different context-conditioned formations.

Balanced active relations may have a scalar total of zero without being absent.

The relevant information can therefore reside in:

```
presence
+ cancellation
+ relational orientation
+ chronology/context
```

rather than in a one-to-one mapping between stored cell and source position.

That is the mechanism this public replication protocol is designed to test.

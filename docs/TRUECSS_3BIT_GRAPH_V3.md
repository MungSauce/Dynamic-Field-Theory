# trueCSS 3bit V3 — Graph-Weighted Live Zero

Status: EXPERIMENTAL / corrected architecture

## Critical distinction

trueCSS 3bit has two different zeros.

**Dead zero**

```
(+0) + (-0) = 0
activity = 0
```

Nothing is participating.

**Live zero**

```
(+1) + (-1) = 0
activity = 2
```

Opposing relations are present and balanced.

Therefore a resolver must never observe scalar net value alone. Its observable state is at least:

```
(net field, activity, relational orientation)
```

Dead zero and live zero share the same net value but are different graph states.

## DCT-frozen trueCSS architecture

Unchanged:
- 1,000,000 physical reusable nodes;
- one active chronological page condition;
- 1,000,000 source positions per conceptual page;
- no serialized page bank;
- no residual/correction stream;
- one chronological target taught at a time;
- exact source-isolated cold replay;
- no node-count or node-width growth.

Only the node relational-weight algebra and matching resolver are changed.

## Fixed graphical substrate

Each physical node has exactly four fixed outgoing relation slots.

The destination of every relation slot is generated by a generic source-independent topology law.

Each relation weight is:

```
-1, 0, +1
```

Four weights are serialized as four 2-bit values:

```
4 * 2 bits = 8 bits = exactly 1 byte per physical node
```

Therefore:
- physical nodes = 1,000,000;
- source-dependent node width = 1 byte;
- total fixed graph-weight substrate = 1,000,000 bytes;
- edge topology does not consume source-dependent bytes because it is generic and regenerated.

No capacity is added as chronology advances.

## Signed-binary live-zero motif

One logical binary relation is a pair of active graph weights.

```
dead zero:       ( 0, 0)
live zero A:     (+1,-1)
live zero B:     (-1,+1)
```

Both live states have:

```
sum = 0
activity = 2
```

but opposite orientation.

A binary bit is therefore carried by the orientation of a balanced relation, not by net amplitude.

Generic chronology/context modifiers may invert the interpretation; the decoder regenerates the same modifiers.

## Terminal representation

Eight live-zero orientations provide 256 binary patterns, enough to map the 206 observed terminal byte identities.

The byte-to-terminal map is source-dependent metadata and is serialized/counted.

## Training

For each terminal bit:
1. q, k, previous decoded context and bit index select two fixed graph-edge slots;
2. the current target plus generic modifier determines orientation;
3. training imposes that the two selected edges are active and opposing;
4. all earlier constraints remain in force.

If an existing graph component makes the requested orientation impossible, the settling law fails at that exact chronology.

The architecture is not changed to rescue it.

## Freeze and replay

Unused edge slots remain 0 = dead.

Participating edge slots become +/-1.

A queried relation must satisfy:
- both edges active;
- sum exactly zero;
- orientation decodes to the expected bit after generic modifier.

Thus a scalar-zero implementation is invalid: it would confuse dead and live zero.

## Applicability criterion

The first experiment measures how much chronology this fixed graph-weight field can absorb before relational contradiction.

If it survives the requested corpus span:
- freeze exactly one byte per original physical node;
- remove source and training solver;
- cold replay from the fixed graph weights and generic resolver only;
- require exact output.

This experiment changes only the relational weight algebra from the prior original trueCSS composite.

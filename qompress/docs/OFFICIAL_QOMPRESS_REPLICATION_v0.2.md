# OFFICIAL Qompress Replication v0.2

Status: OFFICIAL EXECUTABLE REPLICATION CHECKPOINT
Date: 2026-09-19
Project origin: Wesley C.C. Barnett

v0.2 preserves the cold-booted Q-OS v0.1 baseline and adds an executable reflex layer.

Canonical pipeline:

`Q-OS v0.1 -> TruQ byte node -> primed-zero chronology -> page/button field -> seed path -> exact reconstruction/rollback`

A TruQ node contains four Q-cells and has 256 instantaneous configurations. Canonical blank is `0x55`, four primed-zero Q-cells.

The v0.2 reference seed stores only nonzero relational changes. Forward execution reconstructs exact source bytes. Reverse execution applies the same XOR relations backward and must return both the data field and chronology field to all primed-zero.

Current evidence deliberately includes negative cases: page-aligned relational persistence compresses repeated pages strongly but expands random data and simple repetitive text. The next research target is stronger fully-accounted derivation opcodes rather than assuming that reversible chronology alone provides arbitrary history for free.

No Qompress compression claim is valid unless all corpus-specific data, topology, selectors, models and exceptions required for decode are included in the size accounting.

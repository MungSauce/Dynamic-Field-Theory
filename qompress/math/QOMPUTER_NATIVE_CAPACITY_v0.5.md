# Qomputer Native Capacity and Ordered-History Mathematics v0.5

Status: formal architecture correction. This document defines the capacity model that Q-OS, the native language, Qompression, and seed accounting must obey.

## 1. Native Q-position

The active local Q alphabet is

A4 = { -, -+, +-, + }.

Structural VOID is separate:

A5 = A4 union { Ø }.

Primed Zero Pi0 is NOT a sixth independently writable local digit. It is a whole-field predicate: Pi0 holds when the declared allocated field is fully unwound into the primed-zero local formation.

Therefore:

- fixed fully allocated topology: 4 local active possibilities per Q-position;
- sparse topology with independently meaningful allocation: 5 local contextual possibilities per Q-position;
- Pi0 does not multiply the local state count.

## 2. Native 256 x 256 QNode

A QNode has

n0 = 256 * 256 = 65,536 = 2^16

ordered Q-positions.

For a fixed fully allocated node:

C_node = A4^(n0)

and

|C_node| = 4^(65,536)
         = 2^(131,072).

Its ideal distinguishability is exactly

log2 |C_node| = 131,072 bits.

This is 16 KiB of binary-equivalent information capacity, but the native machine object is 65,536 Q-positions, not a byte array.

If VOID is independently storable at every position:

|C_node_sparse| = 5^(65,536)

with ideal distinguishability

65,536 log2(5)

bits.

That larger count is valid only if allocation/VOID is physically represented and counted. Sparse topology is not free capacity.

## 3. Multi-node Qomputer

For M fixed fully allocated QNodes:

N = M * 65,536

native Q-positions.

The terminal configuration space is

C_Q(M) = A4^N

with cardinality

|C_Q(M)| = 4^N = 2^(2N).

Thus the fixed machine has exactly 2N bits of ideal terminal distinguishability.

The machine does not need to grow for a program/history whose unique terminal state already lies in this configuration space.

## 4. One-GiB native machine

If "1 GiB" means 2^30 conventional bytes of binary-equivalent active-state capacity, and one active Q-position carries log2(4)=2 bits, then:

total conventional bits = 2^33,
N = 2^33 / 2 = 2^32 Q-positions,
M = 2^32 / 2^16 = 2^16 = 65,536 QNodes.

Therefore a 1-GiB fixed-topology Qomputer contains:

4,294,967,296 Q-positions

organized as:

65,536 QNodes,

and has:

|C_1GiB| = 4^(2^32)
         = 2^(2^33)
         = 2^8,589,934,592

possible active terminal configurations.

This number is enormous, but it is exactly the number of distinguishable states available to a 1-GiB binary-equivalent memory. Native organization changes the semantics and transition law, not Shannon counting capacity.

For decimal 1 GB = 1,000,000,000 bytes, the exact fully active information budget is 8,000,000,000 bits and therefore at most 4,000,000,000 active Q-positions if arbitrary partial nodes are allowed.

## 5. Terminal configuration versus ordered history

Let H be the legal ordered history language generated by the native instruction system.

Let

F : H -> C_Q

map a complete legal history to its terminal Q configuration.

Exact reversible history storage requires F to be injective on the supported history set:

F(h1) = F(h2) => h1 = h2.

Therefore a fixed machine can distinguish at most

|C_Q|

different legal histories without growing.

This does NOT mean the terminal configuration literally contains many simultaneous snapshots. It means one terminal configuration can be the unique endpoint/identifier of one complete ordered history, and reversal can regenerate that history.

## 6. Unrestricted signed-event bound

Suppose N Q-positions each admit two signed activation choices, so every step has

B = 2N

possible independent next events.

Then unrestricted length-T histories number:

|H_T| = (2N)^T.

A fixed fully allocated Q-field can represent all such histories injectively only if

(2N)^T <= 4^N.

Taking log2:

T log2(2N) <= 2N.

Hence:

T_max = floor(2N / log2(2N)).

Examples:

One 256x256 QNode:
N = 2^16,
log2(2N) = 17,
T_max = floor(2^17 / 17) = 7,710 unrestricted signed-event turns.

One 1-GiB binary-equivalent fixed machine:
N = 2^32,
log2(2N) = 33,
T_max = floor(2^33 / 33) = 260,301,048 unrestricted signed-event turns.

These are WORST-CASE unrestricted branch bounds, not the intended Qompression grammar.

## 7. Legal-language / contextual bound

Qompression is useful only when the native language makes the legal branch set much smaller than the unrestricted 2N choices.

If the t-th reverse state has b_t genuinely legal alternatives, then the distinction required by one legal path is bounded by the legal tree:

I(h) = sum_t log2(b_t)

for the rectangular/equiprobable branch model, or more generally by the log-cardinality/rank of the legal history set.

A fixed N-position active Q-field can represent that legal history without growth whenever:

I(h) <= 2N

and the terminal mapping is injective.

If the average legal branch information is h_bar bits per turn, then the approximate fixed-capacity chronology depth is:

T_max ~= 2N / h_bar.

This is the mathematical location of the Qompression opportunity.

The machine does not gain extra arbitrary-data capacity. Instead, a fixed native machine plus deterministic language/grammar can regenerate long structured outputs from terminal states whose distinguishing information is far smaller than the expanded output.

## 8. Native application expansion

Let M be the frozen Qomputer machine/language implementation.

Let S be a terminal native app configuration in C_Q.

Let G_M(S) be the deterministic expanded application/output produced from S.

The expanded length |G_M(S)| may be much larger than the physical size of S.

That is legitimate compression when:

1. M is fixed/shared rather than document-specific hidden data;
2. different supported apps requiring different outputs map to distinguishable states;
3. S alone, together with fixed M, reconstructs the output exactly;
4. all app-specific persistent topology/state is counted.

The number of distinct outputs reachable under fixed M cannot exceed the number of distinct seed configurations used:

|range(G_M)| <= |C_Q|.

Individual outputs, however, can be arbitrarily long if M supplies reusable deterministic structure.

## 9. The integer is a coordinate, not the seed

Because C_Q is finite for a fixed machine, its states may be enumerated:

iota : C_Q -> {0, 1, ..., |C_Q|-1}.

The integer iota(S) is only a coordinate/name for native state S.

It does not increase capacity and need not be the stored representation.

The native Qompression seed is:

SEED(D) = S_D in C_Q,

the actual terminal machine configuration.

An integer index is permitted for proofs, debugging, transport emulation, or verification, but Q-OS must not redefine the native seed as a giant conventional integer.

## 10. Correct compression measurement

For a native implementation, define:

Qsize(S) = number/cost of physically occupied native Q-positions plus any required app-specific topology.

For conventional comparison, use the exact physical encoding cost of those states.

For source/output D:

R_Q(D) = persistent_native_seed_cost(S_D) / conventional_source_cost(D).

Compression exists when:

R_Q(D) < 1

with exact reconstruction and no hidden document-specific state.

A fixed-size machine may represent a much larger expanded application without growing if the application's independent distinguishing information fits inside the machine's terminal configuration capacity.

## 11. Architecture consequence

The dependency order is:

senary/Q substrate
-> QNode(256x256)
-> reversible whole-field transition law
-> native instruction set
-> native language/compiler
-> Q-OS runtime
-> Qompression/native applications.

Qompression is therefore a property of the machine-language-state system, not a conventional archive format layered on top of binary files.
